## 逐维分析

### 1. 指令 (Directive) — C+ (65/100)

**检测信号：**
- ✅ Description 覆盖了几乎所有摘要场景（全面）
- ✅ "When To Activate" 表格清晰（17个触发短语）
- ✅ 每个 Feature 有明确的使用示例
- ⚠️ Description 过长（3 行 300+ 字符），反而稀释了核心关键词
- ⚠️ 20 个 feature 集中在同一个文件中，没有模块化拆分
- ❌ 没有 references/ 目录实现渐进式披露

**评估：**
指令系统基本可用，但缺乏分层设计。20 种格式塞在一个 678 行文件里，LLM 加载后需要从中定位具体指令。Description 包含所有格式枚举，虽然全面但不利于触发精准度。

### 2. 约束 (Constraint) — C (55/100)

**检测信号：**
- ✅ "Behavior Rules" 段（约束行为边界）
- ✅ "Error Handling" 段（错误处理）
- ✅ "Data Safety" 段（数据安全声明）
- ⚠️ 约束偏基础，缺少深度反模式清单
- ❌ **没有 NEVER 规则** — 不知道 AI 不应该做什么
- ❌ 没有定义"输入边界"（最大输入长度、非法输入处理）

**评估：**
约束明显薄弱。虽然有基本的"Behavior Rules"，但缺少显式的 NEVER 禁止项。对于 20 种格式的复杂技能，缺少"当用户意图不明确时不要随意选择格式"等关键约束。

### 3. 冗余 (Redundancy) — D+ (45/100)

**检测信号：**
- ⚠️ 20 个 Feature 中每个都包含几乎相同的模板结构（标题行+分隔线+内容块+统计行）
- ⚠️ FEATURE 1-20 的段落结构几乎完全相同 → 大量重复 Token
- ⚠️ 无 references/ 目录 — 所有内容放在一个文件中
- ⚠️ 每次只激活 1 个格式，但所有 20 个格式的模板都加载到上下文中
- ⚠️ 安全和隐私声明较长（约 30 行），在激活摘要技能时每次都加载

**评估：**
冗余是最大的问题。678 行 / 3994 tokens 中，估计有 **40-50% 是重复模板模式**。例如 Feature 1-20 每个都包含：`## FEATURE N: Name` → `When user says "xxx"` → 模板框 → 说明文字。这 20 个结构可以简化为一个通用格式定义 + 10 行差异化参数表。

## 优化建议（按优先级排序）

### 优先级 1: 消减冗余 🔴（最大收益）
建议将 20 个 Feature 改为「**1 个通用框架 + 1 个参数配置表**」：

```markdown
## 摘要格式框架
每个摘要输出采用统一模板：
```
{EMOJI} {FORMAT_TITLE}
━━━━━━━━━━━━━━━━━━
{CONTENT}

📊 [X] words → [Y] words ([Z]% reduction)
```

## 格式参数表
| 格式 | 触发词 | 标题 | Emoji | 内容规则 | 长度约束 |
|------|--------|------|-------|---------|---------|
| Quick Summary | summarize this | SUMMARY | 📝 | 3-5 bullets | 自动适配 |
| TL;DR | tldr, tl;dr | TL;DR | 🔥 | 1-2 句 | ≤50词 |
| Bullet Points | bullet points | KEY POINTS | 📋 | 3-7 bullets | 1句/条 |
| ELI5 | eli5 | ELI5 | 🧒 | 比喻+简单语言 | — |
| ... | ... | ... | ... | ... | ... |
```

这样可将 4000 tokens 缩减到约 **1500 tokens**，节省 **60%+** 的上下文。

### 优先级 2: 拆 references/ 实现渐进式披露 🟡
- 格式参数表 → 主 SKILL.md
- 详细的输出示例 → `references/examples.md`
- 数据存储/隐私声明 → `references/privacy.md`
- 错误处理详情 → `references/error-handling.md`

### 优先级 3: 补充约束 🟡
- 增加 **NEVER 规则**：不要添加原文没有的信息、不要去掉关键数据、不要输出无关格式等
- 定义输入边界：最大输入长度、特殊内容处理
- 当用户意图模糊时，优先询问格式而非猜测

### 优先级 4: 优化 Description 🟢
- 从 300+ 字符缩短到 120 字符以内
- 保留核心关键词：summarize, tldr, bullet points, eli5, key takeaways
- 去掉枚举式的格式列表（放在 body 中即可）
